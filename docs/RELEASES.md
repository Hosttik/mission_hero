# Релизы Mission Hero → GitHub Pages

## Нерушимое правило

**Любая новая публикация изменённой версии приложения на GitHub Pages обязана повышать номер версии** по SemVer (`MAJOR.MINOR.PATCH`), синхронно изменять:

1. `VERSION` — каноническая версия;
2. `package.json` → `version` — идентичное значение;
3. `CHANGELOG.md` → раздел `## [X.Y.Z]` с перечислением изменений.

Нельзя деплоить изменение приложения без изменения этих файлов. Workflow запускает публикацию **только** после push в `main`, который затронул `VERSION`. Если изменён код, но номер не обновлён — сайт остаётся на предыдущем релизе. Ручного workflow_dispatch нет. Повторный запуск уже опубликованного workflow восстанавливает ту же самую версию, это не новый релиз.

## Процесс

1. Создай рабочую ветку. Измени код и тесты.
2. Выполни `npm test`, `npm run build`, `npm run check-release`.
3. Увеличь VERSION и package.json и заполни CHANGELOG.
4. Создай PR, дождись проверки CI, слей в `main`.
5. GitHub Actions опубликует `dist/` на Pages. Проверь URL и работу в браузере.
6. Только **после подтверждённого успешного деплоя** обнови PROJECT_STATE/HANDOFF с номером версии, URL, run/commit и результатом проверки. Если Actions не завершился — релиз остаётся НЕОПУБЛИКОВАННЫМ, не объявляй успех.

## Настройка Pages (один раз)

В `Hosttik/mission_hero`: **Settings → Pages → Build and deployment → Source: GitHub Actions**.

Ожидаемый адрес после успешного деплоя: `https://hosttik.github.io/mission_hero/` (это ожидаемый URL, не подтверждение публикации).

## Проверки

Workflow на pull request запускает тесты и сборку **без деплоя**. На push в main с изменённым VERSION дополнительно проверяет, что версия больше предыдущей, и публикует статические файлы. Скрипт `scripts/check-release.mjs` проверяет согласованность версии и changelog. Вывод реального деплоя — GitHub Actions, не локальный вывод теста.
