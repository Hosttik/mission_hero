## Краткая суть

Mission Hero — игра для детей 4–7 лет, в которой браузер на стационарном устройстве становится панелью космического корабля, а ребёнок играет также в комнате. Нужен **тестовый прототип**, не коммерческий релиз. Полное ТЗ — `docs/PRODUCT.md`. Подтверждённые решения — `docs/DECISIONS.md`. Там же отдельно обозначены гипотезы и технические предложения.

## Изменения при этом handoff

- Создан README и единый вход `AGENTS.md`.
- Перенесены два исходных документа из восьми раундов продуктового интервью.
- Созданы `docs/COLLABORATION.md`, `docs/ROADMAP.md`, `docs/TASKS.md`, `docs/PROJECT_STATE.md`.
- Принята модель **один активный агент**; следующий исполнитель читает репозиторий, а не историю чата.
- Подключённый GitHub-доступ ChatGPT реально обнаружен и использован для записи файлов в `Hosttik/mission_hero`.
- Agent Relay **не установлен**; для Codex возможна отдельная настройка, но она не является условием того, что ChatGPT может делать PR через GitHub.

## Последняя проверка

Загрузка и создание файлов через GitHub API завершились успешно. Проверка сборки или тестов приложения не проводилась: исходного кода приложения пока нет. При следующем входе проверь состав файлов и актуальные коммиты `main`.

## С чего начать

1. Выполни протокол входа `AGENTS.md`.
2. Возьми `MH-001` из `docs/TASKS.md`.
3. Реши технический стек на основе ограничений прототипа и создай запускаемый каркас — минимум, подтверждающий будущую интеграцию движка/UI/сохранений.
4. При передаче запушь рабочую ветку, обнови статус на `main` и перезапиши этот handoff фактическими проверками и точным следующим шагом.

## Не додумывать

- ТЗ v0.1 ещё не утверждено как целиком финальное: `[П]` и `[Т]` не равны `[Р]`.
- 3–5 недель — оценка для прототипа, не обязательство построить весь идеальный продукт.
- Установка Relay или его hooks в чужую среду не завершена. Не утверждай обратное.
- Создание GitHub-файлов не означает, что они уже синхронизированы в незапущенный локальный Codex; нужен `git fetch/pull`.
